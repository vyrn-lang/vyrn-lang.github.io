std/hints

8 exports, from std/hints.vyrn.

Policy for checking libraries: per-project rule levels and per-line waivers.

A rule is a code, a string this module never interprets; an input file is text with lines. std/vyx-hints uses only this public surface.

import { hint, noPolicy } from "std/hints"
import { Severity } from "std/diag"

export gen fn myHints(path: String) -> String {
    let src = match readFile(path) { Ok(t) => t, Err(e) => "" }
    let mut out = ""
    // ... find something at line 4, column 9 ...
    out = out + hint(noPolicy(), "my/rule", Warning, src, path, 4, 9, "say what is wrong")
    return out
}

A project sets levels with a JSON object under the library's own top-level key, in any JSON file passed to the generator as a constant path:

{ "hints": { "a11y/img-alt": "error", "perf/img-size": "off" } }

policyOf refuses a config that does not parse or names an unknown level: a swallowed fault would report rules on while they are off.

vyrn-ignore <code> on the reported line, or on the line above it, drops that one report. The marker is plain text inside the input's own comment:

<!-- vyrn-ignore a11y/tabindex-positive: the tour sets the order -->
<div tabindex="2">Start here</div>

unusedWaivers fn

std/hints.vyrn, line 224
fn unusedWaivers(p: HintPolicy, src: String, file: String, raw: String) -> String

Reports every vyrn-ignore marker in src that waives nothing. raw is the same report built under strictly; a marker at line L is used when raw reports its code at L or L + 1.

Reports go through hint with p, so hint/unused-waiver is configured and waived like any other rule.

Tests

11 test blocks in std/hints.vyrn. CI runs all of them.

Test names
  • an absent key is the empty policy, not a fault
  • a configured level wins over the rule's default
  • a malformed config is refused, never a silent no-op
  • an off rule emits nothing
  • a hint carries its code, its anchor and its severity
  • a waiver on the line, or the line above, drops that one report
  • a waiver names its code exactly — prefixes do not leak
  • line text is 1-based and ends at the newline
  • a waiver is honoured on its own line and on the line below it
  • a waiver on line one has no line above to consult
  • a waiver on a final line with no newline covers the line past the end
