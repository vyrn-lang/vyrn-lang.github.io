std/jsondec

42 exports, from std/jsondec.vyrn.

The untyped half of fromJson, and the generator of the typed half.

jsonDecoders writes the typed half per target type. What it writes reads the source once through a JsonReader and decodes each value into its slot; it builds no Json tree. It calls this module for the reader, Issues, paths and scalar decoders. Decoding accumulates: a decoder records its failure and returns, and a composite constructs only when every part succeeded. So every decoder returns an Array<T> of zero or one element; empty means the issue is already recorded. Option<T> cannot serve: with T = Option<U> it has no wire form. Every message is the canonical wording, byte for byte. A refused document yields its json.parse Issue alone, and a record's Issues follow its members' declaration order, whatever the document's key order.

The tree accessors (fieldsOf, fieldAt and the rest) serve programs that read a Json from parseJson.

jsonDecoders fn

std/jsondec.vyrn, line 425
gen fn jsonDecoders(t: TypeArg) -> String

Writes the decoders fromJson calls: for each root, the entry that reads a document into Validation<T>, and for each node, the function that decodes the value at a reader's cursor into zero or one value. Generated source cannot spell reserved names, so it writes VyrnRt_ for std/json's, VyrnRd_ for this module's and VyrnWp_ for a where type's predicate.

Test names
  • a decode result is zero or one element
  • integers decode exactly, never through a Float64
  • a sized integer out of range is a type issue, not a wrap
  • a wrong kind is a type issue, and the value is read past
  • paths compose the canonical way
  • a parse error is one issue, keyed json.parse, worded line/col
  • a string's content is its tag
