Why Vyrn

State what must be true of a value, and let the compiler decide how to keep it true. State what a function does with its argument, and let the compiler decide when the memory goes back.

Validated types

A validated type carries its where clause everywhere it goes. The compiler refuses what it can prove invalid and erases the check where it can prove valid. Everywhere else it emits the check, which means every boundary a value arrives at. The playground runs one.

Ownership

A parameter states what the function does with its argument. Nothing is inferred, and there is no lifetime syntax.

The three wordsread, modify, consume

The function looks at the value and does not change it.

fn seatCount(t: read Ticket) -> Int64 {
    return t.seats  // the caller still owns t afterwards
}

Assigning through the parameter is a compile error, and the caller still owns the value afterwards.

The function changes the value in place.

fn addSeat(t: modify Ticket) {
    t.seats = t.seats + 1  // changed in place, still the caller's
}

The caller keeps the value, changed. No second alias to it may exist while the call runs.

The function takes ownership.

fn redeem(t: consume Ticket) -> Int64 {
    return t.id  // the caller may not name t again
}

Naming the value again after the call is a compile error.

vyrn why --cost <file> names the lines that allocate, copy and keep a check. The chapter on ownership walks one.

Non-goals

No garbage collector
Collection time is a cost you cannot see in the source. Ownership is declared instead, and memory is reclaimed at a site the compiler can name.
No async, no await
Two colours of function split a library in half. The host owns the loop; Vyrn owns the state and the logic.
No macros
A generator is ordinary Vyrn that runs at compile time and returns Vyrn source, and vyrn emit-gen prints what it produced. RPC, UI, i18n, OpenAPI and GraphQL are libraries built this way.
No higher-kinded types
The cost lands on every error message, paid by every reader, to serve a few abstractions.
No inheritance, no metaclasses
A protocol states what a type does. A record states what it holds. Nothing needs a third relationship.
No null
Option<T>, Result<T, E>, exhaustive match, and ? propagation. A failure is a value you have to look at.

Predictability

The native binary and the WebAssembly module it is built from must agree byte for byte, floating point included. Every reading is published, and the route harness fails CI when the bytes disagree.
